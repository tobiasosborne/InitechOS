# InitechBase file conformance study

Test material only, studied at product commit `09d52a32`. This directory is
an opt-in differential, separate from the component's accepted 75 suites.
`cases.tsv` names 36 input conditions; each `cases/Cnn/MINT.PRG` is the exact
command recipe, including a final close and `COPY FILE ... TO SAVED.DBF`.
The input is edited in place by REPLACE, then copied; the copy is not an export.
Failed USE commands skip data commands using `LEN(DBF())>0`, avoiding real
III+'s interactive file-name prompt. Error handlers print ordinal and message
and continue, preserving the real error and resumption behavior.

`reference/` contains only real dBASE III PLUS 1.1 output and disk readback.
`observed/` records InitechBase output, never expected output. `REPORT.md`
records findings, issue IDs, the case table, coverage and remaining captures.
Nothing here changes product sources, component registration or existing goldens.

From the repository root:

```
sh apps/initechbase/tests/conformance/build.sh
sh apps/initechbase/tests/conformance/run-host.sh
sh apps/initechbase/tests/conformance/check.sh
```

The last command deliberately fails for known differences. It checks pinned
input/reference hashes, exact alternate bytes (CRLF, padding and DOS EOF),
meaningful original and copied DBF data through an independent Python reader,
memo content excluding block-0 reserved bytes, and rebuilt NDX keys/recnos via
the existing independent NDX reader. Byte-identical damaged NDX files are
compared directly; a changed index must parse and match its real counterpart.
A crash, timeout, missing end marker, missing readback or pending reference
cannot pass. No expected file is generated by these commands. `CASES='C01 C03'`
selects cases in the host runner and comparator; all reference pins are still
verified. `read_dbf.py` is only an independent reader of foreign DBF/DBT data,
including partial records; all fixture generation and orchestration is C/shell.

To reproduce input generation, run `build/.../conformance/fixtures EMPTY_DIR`,
then `diff -r EMPTY_DIR apps/initechbase/tests/conformance/cases`. `fixtures.c`
uses no product code or headers. Its DBF, DBT and NDX geometry comes from the
fixture-verified `dbase3-decomp/specs/file-formats/{dbf,dbt,ndx}.md`; the probes
at or beyond limits are not assumptions about real error behavior. Real captures
settle those behaviors. D fields normally hold **eight** YYYYMMDD bytes; C29
checks the ten-character date *display* with CENTURY ON. C28 deliberately probes
a nonstandard D10 descriptor, rather than calling it a documented date format.

To mint references explicitly (never part of a test):

```
CASES='C01 C03' sh apps/initechbase/tests/conformance/capture.sh /absolute/empty/output
```

Requires `qemu-system-i386`, `mtools`, `sfdisk`, C11 cc and timeout, plus
`DBASE3_DECOMP` (default `$HOME/Projects/dbase3-decomp`) and `DOS33_BOOT`
(default the same corpus root's `initech-manuals-ref/sidekick/dosboot/` OEM
DOS 3.30 image). Exact runtime/media hashes are in `reference-runtime.sha256`.
DOSBox-X was absent on the review machine. The independent driver is
`goldens/dataloss/drive.c`, built unchanged. Each case gets fresh DOS media and
a separate 32 MiB FAT16 data disk; QEMU is a 486 with 8 MiB and fixed virtual
clock, no network. It runs `DBASE MINT`, waits for DOS's CAPTURE-DONE marker,
then captures VGA and reads disk files using mtools. A 30-second outer bound
and the driver's shorter bounded marker wait stop stalled captures. Interrupted
or incomplete runs are pending, never expected goldens. Raw disposable images
and monitor logs remain in the build output and are not checked in.

`retain.sh DEST CAPTURE_ROOT ...` verifies completion and exact input copies
before retaining readback and a SHA-256 manifest (later roots override earlier
ones). It is an explicit research step, never a gate. New captures should be
inspected before promotion. `INPUTS.sha256` pins all fixture bytes; the separate
reference manifest pins all retained oracle outputs. `qualify.sh` checks that
the comparator rejects an altered saved record and accepts date/reserved-byte
normalization. It changes only disposable host readbacks.

The host adapter runs the actual interpreter and codecs using existing
`w2_host.c` with the usual 2 MiB test heap. This is not a proof of target heap
capacity, cooperative yielding, or desktop behavior. Host observations finish
within five seconds each; target-image replay and opening host-written files
in real III+ remain useful independent follow-ups, with recipes in REPORT.md.
