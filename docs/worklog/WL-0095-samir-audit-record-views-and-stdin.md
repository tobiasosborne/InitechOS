## What changed and why

K05/K06 share a visibility seam in workarea.c. FILTER belongs to an area;
DELETED belongs to the interpreter session. nav.c applies that seam while
moving in physical or index order; query.c applies it to scans, LOCATE and
CONTINUE, and searches matching indexed keys for the first visible duplicate.
mutate.c composes scoped writes with visibility. set.c installs/rejects/clears
conditions and implements DELETED ON/OFF. LIST/DISPLAY now show the deletion
asterisk. Direct physical GO and the manual's deleted RECORD/NEXT/current
DISPLAY exceptions remain available. samir_main.c invalidates cached index
walks on USE/CLOSE. Per-area filters clear on close; reused arenas initialize
view state, and decimal display starts at its documented default. Backward
SKIP across a hidden prefix keeps BOF without incorrectly becoming EOF. Predicate
faults are reported as faults; a subsequent GO cannot reuse their diagnostic.

K09 supplies .DBF only if the final path component lacks an extension.
Explicit extensions and dotted directories survive. dbf.c/dbf.h retain typed
missing/access failures; the REPL maps missing to #1, inaccessible to #29,
and malformed DBFs to #15. A dedicated truncated-body check caught the
DBF_ERR_BAD_FILESZ/WA_ERR_IO numeric collision and prevents its return.

K13 replaces the one-read console assumption with a persistent logical-line
framer in pal/line_input.h, called by pal_milton.c. It keeps read-ahead,
splits CR/LF/CRLF across transport reads, handles blank and final unterminated
lines, propagates read failures, and drains/rejects an overlong command rather
than executing a prefix. Reads always use full cooked-CON capacity.

New C program-level oracles: test_samir_audit.c, test_samir_input.c and
test_samir_audit_emu.c. Gates and implementation mutants are registered in
TEST_UNIT_GATES / TEST_EMU_GATES. All SAMIR COM variants depend on the new
framer header. No spec/ file or expected-output golden was changed.

## RED first and mutation proof

Initial host/OS checks reproduced ignored filters, missing asterisks, unknown
DELETED, implicit USE failure and bad missing-file diagnostics. A byte-stream
extraction of the original input algorithm failed 32 checks and the original
COM failed the K13 OS gate on absent rows / combined-command error. Additional
RED checks caught excluded SEEK keys, reused-arena defaults, failure to clear
filters on reopen, stale predicate diagnostics, SKIP 0 validation, and the
truncated DBF body classification. Final boundary review separately went RED
on physical and indexed SKIP before filtered TOP (.T. .T. 4 rather than
.T. .F. 2); the corrected clamp and expanded OS replay went GREEN.

Implementation mutants (host AND the same complete OS oracle):

- FILTER ignored: negative WADDAMS row returns to LIST / wrong navigation.
- DELETED visibility ignored: marked row returns under ON, even with FILTER.
- Marker omitted: true deleted row has no asterisk.
- Default extension omitted: initial short USE fails; both SMKLOG value
  projections also fail in the host oracle.
- Missing-file mapping forced to #15: required #1 text disappears.
- Original one-read stdin algorithm: several commands become one, LIST rows
  disappear. OS mutants returned to SHELL-DONE with triple_fault=0.

Existing SKIP, short-read, drop-write, DO half-read, no-rebuild desktop, pipe
stdin and corpus mutants also passed their negative-proof gates. No assertion
was relaxed or expected output regenerated to match this implementation.

## Frictions and limits

The full host vector initially failed because test_dbf_read.c opened external
TAX/TOURS references RW and test_ndx_build.c wrote beside the external corpus.
They now use verified byte-identical local RW copies / build/ outputs; all old
checks remain. Real index packing still passes its golden and 50/50 mutant.

Legacy Tier-1 tests still loud-skip some absent Sample_Data paths and documented
unimplemented or unresolved edges. The new finding-specific gates run real
REPL commands and target I/O, rather than inheriting those skips. K08 features,
including the separate program-file USE dispatch gap, are outside this change.

Bochs was not run: test-flair-samir-suspend-bochs is the existing SAMIR-family
Bochs leg for the manager. SAMIR boot/write and the new traces have QEMU gates;
no Bochs/86Box parity or new real-dBASE mint is claimed. No all-of-make-test,
remote write, or bd operation occurred.
