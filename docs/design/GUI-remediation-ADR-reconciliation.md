## Part A — Reconciliation

> **OUTRIGHT CONTRADICTION #1 — D1-4 (park/resume `FLAIR_WNE`) is forbidden by ratified text.**
> ADR-0013 §3.4 (*The cooperative yield and clean-exit contract*, normative): *"A tenant does **not** run a loop; its `event`/`idle` handler does the work for one event and **returns to the shell pump.** Returning *is* the yield. A tenant **never** calls `WaitNextEvent` (single spine, E-D2) and **never** runs a nested modal `WaitNextEvent` loop."* D1-4's tenant-authored `WaitNextEvent` analogue — the tenant loops on `AX=0x0010`, parks by stack-swap, and is resumed by an `iretd` into mid-loop tenant code — is precisely the pattern that passage forbids, twice over (tenant-run loop; tenant-called WNE). It is also ungradeable by the ratified oracle model: O-1 (ADR-0013 §7) replays scripted traces into handlers that *"return promptly,"* and a parked-stack tenant has no such handler shape. **The compliant alternative is the fallback D1.4 itself documents: push-callback delivery through the kernel-owned vtable (`procs->event`), yield-is-return.** Ruled as primary in Part B (DEC-AC3-3); the WNE-loop desire is recorded as deferred pending a future §3.4 amendment, not silently absorbed.

> **OUTRIGHT CONTRADICTION #2 — D1.7's launch watchdog is forbidden by ratified text.**
> ADR-0013 §3.4 / BC-4: non-yielding tenants hang the desktop, which is *"period-authentic cooperative behaviour and is explicitly NOT to be fixed with preemption or a **shipping watchdog**"*; only a **test-only** bounded tick budget may detect non-termination. D1.7's `NO_REGISTER` mutant arms a loader watchdog that *"kills via `kill` and reports"* within a tick budget — a shipping kill path. Descoped to oracle-side detection in Part B/Part C.

## Part B — Amendment DEC blocks

### ADR-0013 Amendment AC-3 (proposed) — the Initech Toolbox Gate and disk-launched tenants

> **DEC-AC3-1 — Disk-launched FLAIR tenants; parameterized InitechMZ load bases.**
> Per-file native (GUI) tenant loading — deferred by ADR-0013 §6/§8 — is hereby ratified for disk-launched GUI tenants, lifting that deferral narrowly. A disk GUI tenant ships as an **InitechMZ flat-32 image** (DEC-08a format unchanged: content dispatch per DEC-08a.4; the `e_res[0] == MZ_INITECH_TAG` gate and the foreign-MZ panic per DEC-08a.5 apply verbatim). DEC-08a.1/.2 are **extended** (not reinterpreted) to parameterized placement: `mz_apply_relocs` relocates against an arbitrary flat `load_base`, and `psp_build` constructs the PSP at an explicit address — the canonical EXEC path (`PROGRAM_BASE`/`PROGRAM_IMAGE`, `EBX = PROGRAM_BASE`) is byte-identical and unchanged. The V1 tenant load carves the code image from the master FLAIR heap (`FLAIR_CLASS_GENERAL`), builds the PSP at the block head (env inherit-empty), relocates, and transfers with `EBX = block PSP`. **Carve/free discipline:** tenant launch carves code→handle→records→data and tears down in strict reverse (data→records→handle→code), preserving the AC-2 §4 LIFO free-list pairing and the O-3 avail-stable invariant. V1 enforces **one resident disk tenant** (kernel slot, fail-loud `TENANT-SLOT-BUSY`); V2 is an array-of-slots change with DOS-heap-per-tenant explicitly deferred (`int21_mcb_bind_program`'s single-window bind stands). Keeping `PROGRAM_BASE` free preserves concurrent class-2 text-tenant EXEC per §3.2.
>
> *Oracle:* host fixtures for parameterized `mz_apply_relocs` + `psp_build` at a non-`PROGRAM_BASE` address (mutation-proven), plus the on-metal `TENANT-LOAD`/`TENANT-REGISTER` golden trace driven by the `app_launch` clip.

> **DEC-AC3-2 — The Initech Toolbox Gate (INT 0x81).**
> The FLAIR API surface for disk tenants is a single software-interrupt gate: **vector 0x81, 32-bit trap gate (type 0x8F), DPL=0, selector 0x08** — the DEC-04a.1 gate discipline for software-int surfaces. Function code in `AX` (sparse map: 0x00xx lifecycle, 0x10xx events, 0x20xx windows, 0x30xx QuickDraw, 0x40xx controls, 0x50xx menus, 0x60xx scrap, 0x70xx misc); scalar/pointer arguments cdecl on the trapped stack, read by the dispatcher above the locked 68-byte `int_frame_t`; result/error in `EAX` (Boolean in `AL`, errors negative). The dispatcher emits one `TENANT-GATE ax=…` serial line per call in debug builds. Vector/map locked as Rule-8 spec-data. Occupancy verified: 0x21 (INT 21h), 0x22–0x24 (DEC-10 handlers), 0x28–0x37 hardware-reserved (DEC-04a.2 — untouchable), 0x80 (IDT self-test); 0x81 is clear.
>
> *Oracle:* host property suite over the gate dispatcher (AX demux, frame-relative arg reads, negative-error convention) + the `TENANT-GATE` trace as the D1/D2 oracle backbone; AX-demux-skip mutant RED.

> **DEC-AC3-3 — Tenancy lifecycle and event delivery: push-callback, yield-is-return.**
> Event delivery is **push-callback through the kernel-owned vtable** — the ADR-0013 §3.4-compliant mechanism. The tenant's registration record (`FlairTenantRec`: tag `'FLTP'`, `namePtr`, `imageBase`, `imageLen`, `evBufPtr`, `eventProc`) is **link-synthesized**: `seed_flair.ld` / the TPS MZ-wrap pass resolve `eventProc` and the string/blob pointers at link time, so no Pascal source ever forms an address (preserving the ADR-0007 DEC-02 zero-growth boundary — no `@`, no procedural types). The kernel validates that every record pointer lies within `[imageBase, imageBase+imageLen)` (fail-loud `TENANT-REGISTER-BAD`), performs the AC-2 three-block carve, stamps `FLAIR_APP_MAGIC`, and installs the kernel-owned vtable (`open=NULL`, `event=disk_tenant_event`, `close=disk_tenant_close`). Events are delivered by copying the cooked `EventRecord` into `evBufPtr` and calling `procs->event`; **returning is the cooperative yield** (§3.4 verbatim); idle slices arrive as dispatched `nullEvent`s. Registration makes the tenant resident; the separate KEEP_RESIDENT trap is dissolved. Exit: `FLAIR_EXIT → FlairProcess_terminate`; crash with the faulting pointer inside a registered image range → `FlairProcess_kill` (never `close()`, never re-entered tenant code), with fail-loud halt preserved for all non-tenant faults; close box on a tenant-owned window terminates the tenant (the anti-initech-8fhu rule) — `HideWindow` remains shell-furniture-only. **No shipping watchdog** (BC-4): a tenant that never registers simply never appears; detection is oracle-side.
>
> *Oracle:* O-1-style host routing suite over `disk_tenant_event` + emu mutants `NO_REGISTER` (tenant absent, desktop intact), `DOUBLE_LAUNCH` (`TENANT-SLOT-BUSY`, no partial install), `EXIT_LEAK` (avail drift), `CLOSE_STALE_FOCUS` (post-close keystroke cannot reach the dead tenant) — all RED.

> **DEC-AC3-4 — Foreground sequencing for windowless registration.**
> Registration links the process list **without** foreground affirmation (the tenant owns no windows yet). The first `FLAIR_NEWWINDOW` from the registered tenant allocates the `WindowRecord` + region trio from the tenant's RECORDS arena, binds `refCon`, raises the group, affirms `FLAIR_APP_FG` (demoting the previous head), and swaps the band-2 menubar through the existing `flair_live_finish_tenant_switch` path. `SETMBAR` before the first window is legal and takes effect at affirmation.
>
> *Oracle:* emu double-click → window-appears → click-inside → clean-exit clip with the menubar-swap assertion (O-5 pattern); a register-without-window mutant leaves the previous foreground undisturbed (RED if affirmed early).

### ADR-0007 Amendment — the TPS Pascal Toolbox binding (next free DEC numbers)

> **DEC-09 — The FLAIR Pascal binding: zero subset growth.**
> Turbo Initech-compiled applications reach the FLAIR Toolbox exclusively through the Initech Toolbox Gate (AC-3 DEC-AC3-2: vector 0x81, function code in `AX`, cdecl arguments on the trapped stack, result/error in `EAX`; vector and AX map are locked Rule-8 spec-data). The binding surface is expressed **entirely within the ratified DEC-02 subset — zero subset growth**: opaque handles as `LongInt` tokens; the `FlairEvent` record is a flat scalar-field record passed by `var`; strings are `ShortString` converted to ASCIZ in the stub layer; external routines are declared through the existing B8 linkage mechanism (DEC-05's separately-assembled-RTL precedent). No pointers, units, `@`, or nested records are invoked; nothing is pulled from the DEC-02 deferred table (C-2 respected).
