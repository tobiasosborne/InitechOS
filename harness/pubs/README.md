# Publications correctness gates

Binding source: `docs/pubs/DESIGN-REFERENCE.md` (PUB-REF-0001), especially
11.1-11.5, GC-01/03/04/05/06, PG/TY/PN. Beads: initech-ipu5.5 and
initech-ipu5.6. Factory implementation is C plus make and thin shell;
LuaLaTeX is the ratified D-11 document exception.

Run with `INITECH_QMP_STDIO=1` when QEMU is involved:

```
make pubs test-pubs-build test-pubs-repro test-pubs-screens
make test-pubs test-pubs-mutant test-pubs-honesty test-pubs-families
```

`test-pubs` joins TEST_UNIT_GATES beside `test-pubs-build`. It includes the
live screen replay leg; the existing TEST_EMU_GATES entry remains as well.
`SKIP_PUBS=1` on the two aggregate targets prints SKIPPED and explicitly
says it is not a pass. Normal runs do not skip missing tools.

## Command coverage

The house class writes `.cmds` (the one documented-command list),
`.mentions` (inline `cmd` uses), `.screens` and `.replays` beside each PDF.
Every reference entry registers what it documents through
`RegisterCommand{NAME}{KIND}{STATE}{ENTRY}` (initech-syntax.sty): the IBM
`DosEntry` and the summary `CommandEntry` register their own name,
`AlsoNamed{ERASE}` adds another name to the entry it is in, and
`FunctionEntry{3F}` registers `INT21:3F` (KIND int21). A `.cmds` line is
`NAME|KIND|STATE|ENTRY`; KIND is internal, external, batch, config or int21;
STATE is GATED, or DRAFT for an entry carrying a draft marker. Device names
and environment variables are `file`, not `cmd`. `UnknownCommand` marks a
deliberately invalid command in a negative teaching example, and
`UnshippedCommand` a DOS 3.3 command this version does not ship (only in
DRAFT-marked text).

`pubs-inventory` writes the shipped inventory as `NAME|KIND` lines:
internal from the preprocessed command.c dispatch table; int21 from the
actual `ah_is_listed()` controlled register (int21.c, included by a probe);
external from the build's `FLAIR_FIXTURES` APPS executables (data files such
as 123.MNU are excluded by extension); batch and config from the real
`batch_classify` and `config_sys_parse` (dos_surface_inventory.c), asked
about every quoted upper-case word of batch.c and config_sys.c. The int21
register is the controlled function surface, including the registered legacy
FCB range; it does not claim that each subfunction has a functional
implementation.

`test-pubs-commands` checks the InitechDOS books together (the Reference
and the User's Guide `.cmds`) against the inventory in both directions, by
NAME|KIND pair: a documented pair the build lacks is DOC-NOT-SHIPPED unless
its entry is DRAFT; a shipped pair with no entry is SHIPPED-NOT-DOCUMENTED
unless its NAME is in `harness/pubs/pilot.allow`. Inline commands are
checked by their first word against the shipped names. Every omission is
printed on every gate run; stale allowances (nothing shipped by that name,
or every shipped pair of it documented) fail. The shrink check compares with
both HEAD and HEAD^ using read-only git show, so an added row is RED for the
commit that adds it and the next. Other books cannot silently add command
entries or mentions without their own shipped inventory: the aggregate
reports COMMAND-SURFACE.

## Replay and lints

Every printed Screen (and every F-IBM `Shot` transcript) must name a
committed `screens/name.txt` and have a `screens/name.keys` trace plus a
SCREENS row `name|marker|disk`. The .keys file is the sole keyboard source
and starts with the two Enters that answer the startup date/time prompts.
`disk` is empty for the practice diskette as shipped (its AUTOEXEC.BAT sets
PATH) or `noautoexec` for the same diskette without AUTOEXEC.BAT, the only
case in which InitechDOS asks for the date and time (the startup screens).
The capture route boots COMMAND.COM, settles on the named serial marker
(`marker#N` = its N-th occurrence), captures pixels and decodes the console.
The gate compares those bytes using the same C comparator exercised by
CHANGED_SCREEN.

`begin{Transcript}{path/stem}` / `end{Transcript}` prints `stem.txt` and
registers `stem.prg` for replay through the SAMIR host PAL/interpreter.
Expected bytes are authored separately and never regenerated by the gate.
The InitechBase replay specimen prints a real salary calculation and its
program. That specimen is not the unwritten InitechBase manual.

ASCII scanning covers all of pubs (printable ASCII and LF; factory shell
and make may also contain tabs). Vocabulary, years and metadata scanning
covers publication .tex/.txt/.prg files, with TeX comments removed per
VO-18. The deny-list is checker configuration, not printed prose. Factory
.sh/.mk/.cls/.sty/latexmkrc and fonts.lock receive the ASCII check; their
implementation vocabulary is not publication prose. The only exempt
publication is exactly `pubs/common/colophon.tex`. Part numbers are parsed
as PN tokens, and 2504 is exempt from the year check only immediately after
`extension`; other four-digit years after 1993 fail, including year ranges.
Font hashes are checked against fonts.lock. Build overfull cap remains 0.

`test-pubs-mutant` uses isolated build fixtures. It typesets a real fake
CommandEntry, removes a shipped command's allowance, changes one transcript
byte and injects a banned word. Additional named cases cover ASCII, years,
part number, print code, allow-list growth, an actual overfull TeX box and
a changed screen byte. Each case must fail with its specific diagnostic.
The source tree and pilot allowance file are never mutated by this test.

## Scope left for the programme

This pilot is not the complete GC-01 inventory for all products: batch and
CONFIG.SYS entries, switches, keys, menus, SAMIR functions and the other
product surfaces still need their own build-derived inventories and books.
The remaining GC contracts (messages beyond the existing generated DOS
appendix, version/release/gate-citation/completeness/canon checks) are not
claimed by this gate. The books remain DRAFT, and press PDF/X production
profiles, print proofs and outstanding artwork remain programme work.

## The InitechWord manuals (bead initech-ipu5.10)

The InitechWord books (`pubs/manuals/initechword-reference`,
`-workbook`, `-install`) have their own shipped inventory, MEASURED from
WORD.EXE: `iword_probe.c` compiles `os/iword/app/face_a.c` over the real
document core with a recording Toolbox mock (the test_iword_face.c pattern)
and drives it. Kinds: `wpkey` (every key or Home sequence that changes the
state from a fixed probe document; a modified key that does exactly what
its plain key does is listed as an alias `Ctrl-F10=F10`; the keys acting on
a block as `Block:F6`), `wpmenu` (every menu choice whose result differs
from both the unchanged prompt and Cancel, named by its keystroke path and
the name the screen shows: `Shift-F8,1,3,2=Center`), `wppull` (the menus[]
handed to SETMBAR), `wpcode` (the labels of the locked
spec/iword/reveal_codes.h, read from its text), `wpmsg` (every status-line
message, observed by driving the program into it; every literal face_a.c
passes to error() or shows as a prompt must be observed, else
MESSAGE-UNPROBED).

`iword_check.sh` (`make test-pubs-iword`, in `test-pubs`): COMMANDS -- the
Reference registers (`\Documents`, initech-wpc.sty -> `\RegisterCommand`)
exactly the shipped surface, both directions, with an empty allow-list
(`iword.allow`); TEMPLATE -- the template strip's cells are exactly the
F-key bindings (PK-14 "generated from the shipped key map"); KEYS -- every
`\K` key in running text is shipped (aliases accepted); FEATURES -- every
Workbook lesson feature and `\RefEntry` is a Reference entry; REPLAY --
every keystroke the books print (`\BeginReplay` .. `\EndReplay`, `\Type`,
`\Press`, `\Choose` ... -> `main.wpreplay`) is replayed on WORD.EXE, one
launch per replay, in book order on one scratch data volume per book, and
every printed screen (`screens/*.scr`, 76 x 24 cells + attributes) equals
the replay byte for byte; PRINTED -- committed and printed screens agree.
`make pubs-iword-screens` rewrites the screens (review the diff).

FLAIR figures (`\FlairShot`): `pubs/screens/flair_capture.sh` boots the
flagship desktop with the shipped data volume, opens WORD.EXE with the
opening of the locked spec trace FLAIR_IWORD_TYPE_SPEC, types the figure's
`flair/<name>.trace`, screendumps at FLAIR-LIVE-OK, and `ppm_grey_png.c`
crops and greys it through the union of the colours of spec/assets/
clut.json and color_canon.json (an unlocked colour is RED). The PNGs are
binary, so they live in `fixtures/pubs/<book>/`; `test-pubs-flair-screens`
(in `test-pubs-screens`) re-captures and compares them byte for byte.

`iword_mutants.sh` (`make test-pubs-iword-mutant`, in `test-pubs-mutant`):
FAKE_KEY, DROPPED_ENTRY, TEMPLATE_CELL, UNSHIPPED_KEY, CHANGED_SCREEN,
CHANGED_KEYSTROKE, UNPROBED_MESSAGE, NO_BLOCK_ON (a real face_a.c mutant:
the probe built with IWORD_MUT_NO_BLOCK_ON loses the "Block on" message the
Reference documents), FOREIGN_FEATURE, ENTRY_ORDER (the AN-11
letter-by-letter check of initech-wpc.sty).
